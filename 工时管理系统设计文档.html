01系统概述

面向公司内部的工时登记与统计管理系统，解决员工日常工时填报、项目工时归集、人员与权限管理的需求。

设计目标

  • 规范化工时填报：员工每天按项目登记工时，系统自动校验单日总工时不超过 12 小时
  • 项目维度的工时归集：工时与项目关联，支持按项目、按人员、按时间维度统计汇总
  • 灵活的权限控制：基于 RBAC 模型，自定义角色 + 菜单级权限分配，不同角色看到不同功能菜单
  • 账号生命周期管理：账号支持启用/停用，停用后无法登录系统

系统边界

本期范围（V1.0）：用户管理、角色管理、项目管理、工时管理四大模块，含登录认证与菜单权限。
不在本期范围：移动端、工时审批流、考勤打卡对接、薪酬计算、LDAP/SSO 集成（预留扩展）。

02功能模块设计

系统共四大功能模块，下文逐一展开详细设计。

2.1 用户管理 身份认证

管理系统中所有可登录的用户账号，包括账号信息维护、密码管理、账号启停控制。

功能点清单

#功能点说明操作角色
1用户列表分页展示所有用户，支持按姓名/账号/状态搜索筛选系统管理员
2新增用户填写账号、姓名、手机号、初始密码，创建后默认「启用」状态系统管理员
3编辑用户修改基本信息（姓名、手机号），不可修改账号（唯一标识）系统管理员
4账号启用/停用停用后该账号无法登录系统；启用后恢复登录。已登录的停用账号，下次请求自动登出系统管理员
5重置密码管理员重置用户密码为默认值，用户首次登录后可自行修改系统管理员
6修改密码用户自行修改密码，需校验原密码所有用户
7登录认证账号 + 密码登录，校验账号存在性、状态为启用、密码正确性公开
8分配角色为用户分配一个或多个角色，角色决定可见菜单系统管理员
密码安全策略：密码存储使用 BCrypt 加密（不可逆），不存明文。初始密码建议 8 位以上，包含字母+数字。连续登录失败 5 次锁定账号 30 分钟（V1.1 可选）。

2.2 角色管理 权限控制

采用 RBAC（基于角色的访问控制）模型：角色是权限的集合，用户通过分配角色获得权限。权限粒度控制在菜单级别。

功能点清单

#功能点说明
1角色列表展示所有自定义角色，含角色名、描述、关联用户数
2新增角色自定义角色名称和描述
3编辑角色修改角色名称、描述
4删除角色已被分配给用户的角色不可删除，需先解除关联
5菜单权限配置树形勾选菜单，为角色分配可访问的菜单。支持父子菜单联动（选父菜单自动选子菜单，取消子菜单自动取消父菜单）
6角色分配用户在角色详情中查看/添加/移除关联用户

预置角色

角色名说明可见菜单
系统管理员系统最高权限，管理所有配置用户管理、角色管理、项目管理、工时管理（全部）
项目经理管理所属项目及成员，查看项目工时项目管理（自己的）、工时统计（项目维度）
普通员工登记和查看自己的工时工时登记、我的工时
权限校验链路：用户登录 → 后端根据用户角色查询关联菜单 → 前端渲染可见菜单 → 每次接口请求后端校验该用户是否有对应菜单权限（防止绕过前端）。

2.3 项目管理 业务对象

项目是工时登记的业务载体。员工只能在自己关联的项目下登记工时。

功能点清单

#功能点说明
1项目列表分页展示所有项目，支持按名称搜索、按状态筛选（进行中/已结束）
2新增项目填写项目名称、选择项目经理、设置起止日期
3编辑项目修改项目名称、项目经理、起止日期、状态
4删除项目软删除。已关联工时记录的项目不可物理删除，仅可标记为「已结束」
5项目成员管理在项目详情中添加/移除成员。只有项目成员才能在该项目下登记工时
6设置项目经理项目经理从系统用户中选择，一个项目一个项目经理
关键约束：员工工时登记时的项目下拉列表 = 该员工参与的、状态为「进行中」的项目集合。已结束项目不出现在新增工时的下拉中，但历史工时仍可查看。

2.4 工时管理 核心业务

工时管理是系统核心模块，支持员工每天按项目登记工时，系统强制校验单日总工时上限。

功能点清单

#功能点说明
1工时登记选择日期 → 添加一个或多个项目 → 每个项目分别填写工时和备注 → 提交保存
2多项目拆分登记同一天可在多个项目下分别登记工时，系统自动汇总当日总工时
3工时上限校验单日所有项目工时之和不能超过 12 小时。超过时前端拦截 + 后端二次校验
4编辑工时可修改当天已登记的工时（修改项目、工时、备注），同样受 12h 上限约束
5我的工时按日历/列表查看自己已登记的工时，支持按日期范围、项目筛选
6工时统计项目经理可查看所属项目的工时汇总；管理员可查看全员工时报表
7工时汇总报表按项目/人员/时间维度汇总，支持导出 Excel
核心校验规则（12h 上限）：
① 前端实时计算：每修改一个工时输入框，实时累加当日所有项目工时，超过 12h 时进度条变红、禁用提交按钮并提示
② 后端二次校验：提交时后端查询该用户当天所有工时记录总和（含本次新增），若超过 12h 返回错误拒绝保存
③ 单项目工时约束：每个项目工时必须 > 0 且 ≤ 12h，支持 0.5h 步长

工时登记交互说明

  1. 进入工时登记页面，默认选中当天日期
  2. 页面展示当前用户关联的「进行中」项目列表供选择
  3. 点击「添加项目」新增一行：项目下拉 + 工时输入 + 备注输入
  4. 可添加多行（多个项目），每行独立填写
  5. 底部实时显示「当日总工时 X.Xh / 12h」进度条
  6. 总工时 > 12h 时：进度条变红、显示警告文案、提交按钮置灰
  7. 校验通过后点击「提交」，后端保存并返回成功
  8. 同一天再次进入：加载已登记数据，可编辑后重新保存

usernameVARCHAR(50)登录账号唯一，非空
passwordVARCHAR(100)加密密码（BCrypt）非空
nameVARCHAR(50)姓名非空
phoneVARCHAR(20)手机号—
statusTINYINT状态：1=启用，0=停用默认 1
created_atDATETIME创建时间—

4.8 工时记录表 timesheet 核心表

字段类型说明约束

updated_atDATETIME更新时间—
12h 上限的数据库层保障：建议在 timesheet 表上创建联合索引 (user_id, work_date)，提交时通过 SELECT SUM(hours) FROM timesheet WHERE user_id=? AND work_date=? 快速校验当日总工时。业务层在保存前校验：当前新增/修改后的总工时 ≤ 12h。

05接口设计（API）

RESTful 风格，统一前缀 /api/v1，所有接口需携带 Token（登录接口除外）。

5.1 认证接口

POST/api/v1/auth/login

登录认证，返回 JWT Token

请求体：
{
  "username": "zhangsan",
  "password": "******"
}

响应：
{
  "code": 200,
  "data": { "token": "eyJhbG...", "name": "张三", "roles": ["普通员工"] }
}
POST/api/v1/auth/change-password

修改密码，需校验原密码

5.3 角色管理接口

PUT/api/v1/roles/{id}/menus配置菜单权限

5.4 项目管理接口

方法路径说明
GET/api/v1/projects项目列表（分页+搜索）

PUT/api/v1/projects/{id}编辑项目

5.5 工时管理接口

POST/api/v1/timesheets

提交工时登记（支持批量提交当天多个项目工时）

请求体：
{
  "work_date": "2026-08-05",
  "items": [
    { "project_id": 1, "hours": 6.0, "remark": "需求评审+用例编写" },
    { "project_id": 3, "hours": 3.5, "remark": "接口联调测试" }
  ]
}

响应：
{
  "code": 200,
  "message": "保存成功"
}

校验失败响应（总工时超12h）：
{
  "code": 400,
  "message": "当日总工时 13.5h 超过上限 12h，请调整"
}
方法路径说明
GET/api/v1/timesheets/my我的工时列表（按日期范围+项目筛选）
GET/api/v1/timesheets/my/{date}查看某天工时详情（回显编辑用）
PUT/api/v1/timesheets/{date}修改某天工时（整体覆盖）
GET/api/v1/timesheets/stats工时统计（按项目/人员/时间维度汇总）
GET/api/v1/timesheets/export导出工时报表（Excel）

06核心业务规则

所有业务规则的汇总，开发与测试均以此为验收依据。

#规则说明校验层
R1账号停用不可登录登录时校验 status=1，否则返回「账号已停用」后端
R2登录密码加密BCrypt 加密存储，不可逆后端
R3菜单权限动态渲染前端菜单根据用户角色关联的菜单列表动态渲染后端+前端
R4接口权限二次校验后端每个接口校验当前用户是否有对应菜单权限后端
R5角色删除约束已被分配给用户的角色不可删除后端
R6项目删除约束有工时记录的项目不可删除，仅可标记为「已结束」后端
R7工时项目范围登记工时只能选择自己参与的、进行中的项目后端
R8单项目工时 > 0每个项目的工时必须 > 0前端+后端
R9单日总工时 ≤ 12h同一天所有项目工时之和 ≤ 12h，否则拒绝保存前端+后端
R10工时步长 0.5h工时输入支持 0.5 的倍数前端+后端
R11同日可多项目同一天可在多个项目下分别登记工时业务
R12同日同项目唯一同一用户同一天同一项目只有一条工时记录后端
R13工时可编辑已登记的工时可修改，同样受 12h 上限约束业务

07非功能性需求

安全

  • 密码 BCrypt 加密存储，禁止明文
  • 接口认证使用 JWT Token，有效期 8 小时，支持续签
  • 所有写操作接口做权限校验，防止越权（如普通员工不能调用用户管理接口）
  • SQL 参数化查询，防止注入

性能

  • 工时列表查询响应时间 < 500ms（数据量 10 万条以内）
  • 关键索引：timesheet(user_id, work_date)、timesheet(project_id)、project_member(user_id)
  • 工时统计报表支持按月/按季度聚合，大数据量时考虑预计算或缓存

兼容性

  • 浏览器：Chrome 90+、Edge 90+、Safari 14+
  • 最小分辨率 1280×720，推荐 1920×1080

扩展性（预留）

  • 工时审批流：预留 timesheet 表 status 字段扩展（草稿/待审/通过/驳回）
  • LDAP/SSO 集成：预留认证接口扩展点
  • 移动端：API 已 RESTful 化，可直接对接移动端或小程序
